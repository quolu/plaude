# site-msa2/t5 — MS-A2 配備

`plaude-web:latest` を Mac で Vite production build 後に `linux/amd64` image
（`sha256:65aeb0ad01d01aa92d4cdb68be9397489d981328c7eec48c35fe52134e142f93`）として
作成し、MS-A2 へ転送した。MS-A2 の `~/plaude` で `docker compose up -d --no-build`
を実行して `plaude-web` を再作成した。永続データの `./data:/data` は維持した。

既存の公開経路も実測した。Caddy の `plaud.kitepon.dev` site は
`192.168.1.2:18880` を reverse proxy し、cloudflared container は稼働中である。
匿名の `https://plaud.kitepon.dev/` は Cloudflare Access の login URL へ `302` となり、
認証なしで面の内容を返さない。

## 最終試験

- Mac: Vite build が成功し、`linux/amd64` image を作成した。
- MS-A2: `docker compose ps` で `plaude-web` が `healthy`、
  `http://127.0.0.1:18880/healthz` が `ok`。
- origin: `/` が `200` で新しい `index-CNTmcX8Y.js` を返し、
  `/m/mock-safety/audio` の `Range: bytes=0-31` が `206`、
  `Content-Range: bytes 0-31/48526`、`Accept-Ranges: bytes`、32 byte body を返した。
- Caddy: MS-A2 localhost への Host 指定 HTTPS probe が `200` で plaude の HTML を返した。
- public edge: `https://plaud.kitepon.dev/` は Cloudflare Access の `302` を返した。
