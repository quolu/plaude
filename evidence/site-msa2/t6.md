# site-msa2/t6 — 実会議の公開面確認

## 実装

- 13分12秒の端末録音をローカルの `whisper-cli`（`ggml-small.bin`）で起こし、安全教育として `lecture` テンプレートを選び、要約を render して origin へ publish した。録音本文・本番音声はリポジトリに保存していない。
- 実会議の確認で見つかった音声 404 を、現在工程の成立に必要な先行工程由来不具合として修正した。publisher は Plaud の presigned 音声 URL だけを送信し、MS-A2 origin がその URL を pull して `meetings/<id>/audio.mp3` に原子的に保存する。音声本体を publish POST しない。
- 個人 pipeline の `site_origin` をAccess保護された公開URLから、正規の LAN origin `http://192.168.1.2:18880` へ設定した。これによりpublisherはAccess認証画面ではなくorigin APIへ到達する。

## 最終試験

```sh
python3 scripts/test_plaud_inbox_publish.py
python3 -u web-server/test_server.py
git diff --check

# worktree の一時コピーで、既存の依存を再利用して実行（npm installなし）
npm --prefix <staged-worktree>/web run build
docker build --platform linux/amd64 -t plaude-web:latest <staged-worktree>
docker save plaude-web:latest | ssh kite@192.168.1.2 docker load
ssh kite@192.168.1.2 'cd ~/plaude && docker compose up -d --no-build'
```

結果: すべて成功。

- focused publish test は音声URLをpayloadへ含め、成功時だけ完了記録を付けることを確認した。
- origin test は publish後にoriginが音声をpullし、`/m/probe-publish/audio` が `audio/mpeg` を返すことを確認した。
- MS-A2 の実会議詳細は要約・文字起こし・`has_audio=true` で、`Range: bytes=0-31` は `206`、`Accept-Ranges: bytes`、`Content-Range`、32 byte bodyを返した。
- 実会議ページはSPA entry scriptを返し、配布済みscriptに `currentTime`（タイムスタンプシーク）とtemplates viewが含まれる。APIのテンプレ一覧には `lecture` を含む30件がある。
- `https://plaud.kitepon.dev/` の匿名アクセスは `302` でCloudflare Accessログインへ遷移し、中身を返さない。

Gmailでの対話ログイン済み画面確認だけは、この席にブラウザ／Access認証手段がないため未自動化である。匿名遮断とoriginの実データ・音声は上記のとおり確認済み。
