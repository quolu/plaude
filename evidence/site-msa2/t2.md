# t2 — web 会議画面と音声シーク

会議画面のプレイヤーと文字起こし時刻クリックによるシーク経路を維持しつつ、`/m/<id>/audio` に HTTP byte-range 応答を復元した。`Range: bytes=start-end`（単一範囲）に `206 Partial Content`、`Accept-Ranges: bytes`、正しい `Content-Range` を返す。範囲外または不正な range は `416` を返す。

## 検証

- 隔離 worktree で `python3 -u web-server/test_server.py` を実行して成功した。
  - mock meeting の通常音声取得が `200 audio/mpeg`。
  - `Range: bytes=0-31` が `206 audio/mpeg`、`Accept-Ranges: bytes`、`Content-Range: bytes 0-31/<size>`、32 byte body を返す。
  - 会議一覧・詳細、テンプレート CRUD、publish も同じ統合試験で成功した。
- `node --input-type=module --eval …` で `bindTranscriptSeek` のクリック→`currentTime=42` とテンプレート作成フィールド生成を確認した。
- `npm --prefix web run build` は worktree に `web/node_modules` が無く `vite` 未解決のため実行できなかった。依存の install は worktree 観測を汚すため行っていない。
